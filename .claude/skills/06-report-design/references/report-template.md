# Report template — the section skeleton

Copy this, fill it, delete what genuinely does not apply (and say why in §12 if you delete a mandatory
section). Prompts are in *italics* and get removed.

---

# <Question in one line> — <systems used>

> Cast <date>. **v<N> — <converged at round N | round N pending>.** All chart values from
> `.claude/calc/`, re-derived at synthesis. Suites: <list, green>.
> **Redaction tier: private | shareable | counterparty-facing.**
> **Assumptions, flagged not buried:** *<birthplace, timezone era, gender, any fork and its weighting>*

## 0. Decision card

> **<The answer.>** <Confidence>.
> **Do now:** <the one action>
> **The gate:** <the single thing that blocks it>
> **Do not:** <the one thing to avoid>
> **Revisit when:** <trigger, not a date, where possible>

*≤5 lines. If you cannot write this, you do not have a reading yet.*

## 1. The recommendation(s)

*One per decision. Never bundled — if two decisions are being made, they get two recommendations and an
explicit statement that bundling them is itself the risk. Confidence band + what it rests on. If the
confidence about the decision differs from the confidence about the outcome, say both.*

## 2. Why — the arguments, honestly counted

*Which arguments are genuinely independent? Which are echoes of each other or of standing doctrine?
Which are non-chart? Which are specific to this counterparty and which would defeat this structure with
anyone? State the count plainly, and state what the confidence actually rests on — it is often not the
list.*

## 3. The other side, at full strength

*Argue the case you are not recommending as hard as the one you are. If the positive case is decoration,
the reading is not symmetric and is not finished.*

## 4. The chart facts used

*Only what the argument actually uses. Table form. Include the command that reproduces it.*

## 5. Timing

*Phases with hinges, not a list of years. What changes at each boundary. Where two people's clocks
diverge, say so — that divergence is usually the finding.*

## 6. Structure / mechanism

*How it actually works, in plain language: the chain, the bridge, the drain. Vocabulary is not
mechanism.*

## 7. Forks and branches

*Every unresolved ambiguity, carried, weighted, never collapsed. Test the recommendation against each
branch. Where a fork does not discriminate, say so — a conclusion reachable from either branch is not
confirmed by the fork.*

## 8. The tests worth running

*Dated. Cheap. Opposite-signed. Falsifier pre-registered inside each prediction. Mark which are chart
tests and which are ordinary due diligence — do not dress the second up as the first.*

## 9. What would most change this

*Ranked. For each: would it change the reasoning, or the call? Those are different and the reader needs
to know which.*

## 10. The next 30 days

*Concrete, ordered, correctly gated. Say what proceeds regardless and what waits on what. Price each
action: free, one email, a half-day, a lawyer.*

## 11. Windows / scheduling

*Only if a real constraint exists. If the error bars exceed the window, say the window is not usable and
give the one hard boundary instead.*

## 12. Convergence and residuals

*Verification status, naming the round. What was checked in which pass. Then every residual, plainly —
what is `[UNVERIFIED]`, what is out-of-suite, what convention forks remain, what is assumed. A reading
that reports only what survived is not auditable.*

## 13. What earlier versions got wrong

*Table: the claim, why it failed, what it says now. Kept, never quietly deleted — the corrections are the
credibility.*
